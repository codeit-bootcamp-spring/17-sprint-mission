## JCF와 File IO 비교
### JCF방식
- 데이터 영속성 없음
- 간단한 구현(직렬화 불필요)
- 처리 속도 빠름
### File IO 방식
- 데이터 영속성
- 구현 복잡함(직렬화, 예외처리)
- 처리 리소스 필요
- 파일 변조 가능성


## Repository 방식
- **디자인 패턴**이다.
- 비즈니스로직과 접근 로직을 분리하여 비즈니스 로직이 구체적인 데이터 저장 방식에 의존하지 않도록 한다.
	- 비즈니스 로직: 프로그램이 제공하는 기능과 그 기능이 따라야 하는 규칙을 구현한 로직
	- 접근 로직: 데이터를 저장소에 저장, 조회, 갱신, 삭제하는 로직
- 저장소에 있는 도메인 객체들을 마치 메모리에 존재하는 컬렉션처럼 다룰 수 있도록 하는 것.

### 변경 시
- 기존 Create, Update에서 객체 생성, 수정(비즈니스 로직)을 분리해서 save로 통합시킴
- 객체의 생성 및 상태 변경은 Repository 외부에서 수행하도록 함
- Repository는 전달받은 객체를 저장소에 저장, 조회, 갱신, 삭제하는 역할만 담당함
- 저장소가 아닌 객체와 직접 상호작용하는 로직이 main에 노출됨

## Basic \* Service 추가
- Repository 패턴 적용으로 main에 노출되었던 객체와 직접 상호작용하는 로직을 담음.
- Repository를 의존성 주입하여 main에서 Repository와 직접 상호작용하지 않도록 함.
